pyvpn is per-process policy routing for Linux. It sends each app's traffic, and its DNS, out through an interface you choose (wg-jp, tun0, wlan1, …). When that interface is down, the policy falls back to the next interface or the normal default route, or blocks the traffic (kill switch).

Status: alpha (0.0.x). pyvpn-daemon routes traffic and enforces kill switches on Linux. It's tested end to end in network namespaces but hasn't been audited, so don't rely on it alone for privacy yet. A few configuration options are not supported yet. Guides: Installation · Usage.

What pyvpn is (and is not)

pyvpn decides which app leaves through which interface. For example:

Firefox and Steam leave through wg-jp, qBittorrent only through tun0 with a kill switch, ssh to the office through wlan1, everything else through the normal default route.

pyvpn does not create or manage VPN connections. WireGuard, OpenVPN, a provider's app, a second network card or a phone tether bring their interfaces up themselves. pyvpn only routes apps through interfaces that already exist.

It is the client-side counterpart of snake, which picks a tunnel per device on a router.

Concepts

TermMeaning
TargetAn existing network interface (wg-jp, tun0, wlan1) or a name pattern (tun*), plus an optional gateway.
PolicyA named rule: a set of apps, an ordered list of targets, and what to do when every target is down.
App selectorHow a policy finds its apps: launched with pyvpn run, executable path or name, systemd unit, uid or user, Flatpak or Snap ID.
on_downUsed after every target in the list is down: default falls back to the normal route, block drops the traffic (kill switch).
Usable targetThe link is up and has an address (and, with "gateway": "auto", a gateway). Reachability probes are planned.
Destination filterOptional domain, asn: or cidr: rules (snake's rule language) that limit a policy to matching destinations; drop: rules block a destination for the policy's apps.

Target types

  • Point-to-point (tun0, wg0, ppp0): routed with default dev <iface>.
  • Broadcast (eth1, wlan1, usb0): needs a next hop, learned from the interface's own default route or DHCP lease, or set with gateway.
  • Patterns (tun*, wg-jp*): for VPN apps whose interface name changes on each reconnect.

Sockets that are already open keep their route. New connections follow the new policy.

Install

pip install snakevpn
pyvpn --version

The PyPI package is snakevpn; the commands are pyvpn (CLI) and pyvpn-daemon (root daemon). Requirements: Linux with cgroup v2 (the default on current distributions), the nft command (nftables), and root for the daemon. The CLI, including pyvpn run, runs as a normal user. The installation guide covers systemd setup, upgrades and uninstalling.

Configuration

The configuration is JSON, in /etc/pyvpn/config.json by default. Targets name interfaces; policies map apps to an ordered list of targets. The usage guide explains every field.

{
  "version": 1,
  "targets": [
    {"name": "jp",     "interface": "wg-jp"},
    {"name": "nl",     "interface": "tun*"},
    {"name": "office", "interface": "wlan1", "gateway": "auto"}
  ],
  "app_groups": [
    {"name": "browsers", "apps": [{"exe": "/usr/bin/firefox"}, {"flatpak": "com.google.Chrome"}]}
  ],
  "policies": [
    {"name": "Japan browsing", "targets": ["jp", "nl"], "on_down": "default",
     "apps": ["group:browsers", {"name": "steam"}],
     "leak": {"dns_via_target": true, "block_doh": true, "ipv6": "route"}},
    {"name": "Torrents", "targets": ["nl"], "on_down": "block",
     "apps": [{"exe": "/usr/bin/qbittorrent"}], "leak": {"ipv6": "block"}},
    {"name": "Office", "targets": ["office"],
     "apps": [{"name": "ssh"}], "domains": ["corp.example", "cidr:10.20.0.0/16"]}
  ]
}

Commands

pyvpn run -p "Japan browsing" -- firefox   # start an app inside a policy
pyvpn status                               # policies and their active routes
pyvpn apps                                 # policy bindings by cgroup and uid
pyvpn audit                                # what each policy does and does not protect
pyvpn reload                               # re-read the config (root)
pyvpn disable                              # remove all pyvpn rules and routes (root)
pyvpn enable                               # reinstall them after disable (root)
pyvpn test [config]                        # validate a config
pyvpn rules check example.rules            # validate destination rules (snake format)
pyvpn install --write                      # install the systemd unit for the daemon
pyvpn desktop --policy NAME                # print or install a menu launcher

pyvpn rules also has test, import and export subcommands. Put --json before a command for machine-readable output. See the usage guide for examples and real output.

How it works

  • A small root daemon owns nftables, routes and cgroups. The CLI and pyvpn run run unprivileged and talk to it over a unix socket.
  • Apps are identified by cgroup v2 or by uid. An nft rule marks their packets with a fwmark; an ip rule sends that mark to the policy's routing table.
  • A netlink watcher reacts as soon as an interface goes up or down, with no polling. When tun0 disappears, the table switches to the next target, the default route, or unreachable.
  • Each policy table also has a higher-metric unreachable route, so traffic stops rather than leaks if the device route vanishes before the daemon reacts.
  • All Linux code sits behind the Backend protocol in src/pyvpn/platform/base.py, so other systems can be added later.

DNS and leak protection

  • Each policy gets its own DNS stub. nft redirects port 53 from that policy's apps to it, which also catches hard-coded resolvers such as 8.8.8.8. The stub resolves through the policy's interface (plain, DoT or DoH) and returns SERVFAIL rather than falling back to another path.
  • Other apps keep the system resolver. pyvpn does not change system DNS.
  • Per-policy toggles: block DoT (port 853), block known DoH addresses, DoH canary domain, block QUIC, and IPv6 route, block or off.
  • pyvpn audit lists what each policy does and does not protect.
  • Fail closed: with on_down: block, traffic is dropped, never sent through the default route.
  • isolation: netns, which runs an app in its own network namespace, is planned; the daemon refuses it for now.

Limitations and risks

  • Linux only. macOS, Windows and a proxy mode are deferred.
  • cgroup v2 is required. There is no cgroup v1 or hybrid fallback yet.
  • Moving running processes between cgroups can conflict with systemd scopes. Prefer pyvpn run or systemd units.
  • VPN apps with their own kill switch can override pyvpn's rules. pyvpn drops marked traffic that would leave through the wrong interface, but pyvpn audit doesn't report competing rules yet.
  • The daemon needs root; everything else runs as a normal user.

FAQ

Does pyvpn connect to my VPN?
No. Start the VPN with its own tool. pyvpn routes apps through the interface the VPN creates.
What happens when the VPN reconnects and the interface name changes?
Use a pattern such as tun*. pyvpn sees the new interface through netlink and re-installs the route.
Does it change DNS for the whole system?
No. Only apps in a policy use that policy's DNS stub.
What if every target is down?
With on_down: default, the app uses the normal route. With on_down: block, its traffic is dropped.
Why is the PyPI package called snakevpn?
The name pyvpn was already taken on PyPI. The commands are still pyvpn and pyvpn-daemon.
